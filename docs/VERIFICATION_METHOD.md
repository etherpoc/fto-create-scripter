# VERIFICATION_METHOD.md — 戦略検証の標準手順（数字を振り回さないための規約）

2026-06-16 制定。きっかけ: 同じ breakout 戦略の月利が、検証のたびに +2.6% / +0.9% / +1.7% と
振れた。原因は **2軸が混在**したこと → ①約定(フィル)の仮定がバラバラ ②期間がバラバラ
(+2.62%は「2024-26の直近window×実機補正」、+0.9%は「全期間×悲観成行シミュ」、+1.7%は「全IS×実測校正」)。
さらに「実機実測より机上シミュを上に置いた」プロセス過誤。
**今後この規約に従って検証・報告する。** （関連: `docs/IMPROVEMENT_RESULTS.md`, `strategies/standalone/BREAKOUT_README.md`）

> **数字を出すときは必ず「フィル仮定 × 期間」をセットで明示する。** どちらか欠けたら無効。

---

## 1. 証拠の信頼順位（Evidence Hierarchy）— 上が強い

| Tier | 種類 | 用途 | 例 |
|------|------|------|----|
| **T1** | **実ブローカー約定**(ライブ/デモの実トレード) | フィル問題の**最終結論**。机上を上書きする | README「実機転移 FX≈83%/金≈45%」 |
| **T2** | **実測に校正したシミュ** | T1が無い領域の推定 | level約定×実測転移率 |
| **T3** | **理想バックテスト**(レベル約定/スリッページ0) | **上限値のみ**。見出しの数字に使わない | `bo_fast` run_bo_fast |

**鉄則: 新しいシミュ(T2/T3)が既存のT1実測と食い違ったら、シミュを信じず原因を調べる。**
T1を上書きする前に必ず突き合わせる。(2026-06-16 はこれを破って成行シミュ49%をライブ83%より優先し失敗)

---

## 2. 約定(フィル)モデル — 必ず仮定を明示する

ブレイク戦略はフィルに極めて敏感(同戦略でlevel +787R / 成行 +389R = 2倍差)。**単一の数字を出さない。**

- **レベル約定** = ブレイク当足でDonchian levelちょうど(=スリッページ0の逆指値)。**楽観・上限**。
- **成行・次足始値** = 当足確定→次足始値で成行(現EAの素の挙動)。**悲観・下限**(実機よりやや厳しめ)。
- **実機転移率** = 実測。**FX≈83% / ゴールド≈45%**(`BREAKOUT_README` の転移表)。金は実スプレッド過小評価
  +ブレイク〜成行スリッページで剥落大。**ペア(資産クラス)ごとに転移率は違う** → 一律係数で潰さない。

**標準の realistic 推定 = レベル約定 × 実測転移率(資産別)。** 例: basket realistic ≈ Σ(pair level sumR × 転移率)。

---

## 3. コストモデル（既存と統一）

- `net = gross − (往復コミッション + spread)`。spread=0.5p 既定。comm はペア種別(`backtest_breakout.comm`)。
- **gross(コスト0)の数字は罠**。最初から net で出す。
- 1R = リスク額(InpRiskPct%)。月利(加算近似) = sumR_per_month × InpRiskPct%。

---

## 4. ロバストネス（過剰適合除け）

- **WF: OOS=2015-20(未学習) / IS=2021-26。両期間 net+ が robust の最低条件。**
- 単体ペアでなく**両期間**で見る。片方だけプラスはレジーム依存(=YouTube手法/ショートスリーブが落ちた所)。
- ノブ(パラメータ)を少し振っても符号が変わらないか(α=0.2-0.5で効率安定 等)。
- 「効率(sumR/DD)」で比較。月利単独で語らない(サイズで幾らでも変わる)。
- **【期間の罠】直近window(例 2024-26)の数字は“好レジームのチェリーピック”で楽観に出る。**
  **将来期待値は必ず全WF(2015-26)で語る。** 直近windowを見出しに使わない(breakout +2.62%は2024-26の数字)。
  全IS realistic ≈ +1.6-1.9%/月 が forward の正直な値。+2.62%は「直近×実機補正」の上振れ。

---

## 5. サイジング（DD10%への落とし方）

- **size は realistic / T1 の DD から決める。理想バックテストのDDから決めない**(DDを過小評価し過大レバになる)。
- 実測DDにさらに**安全ハーカット**(ライブはBT比1.3-1.5倍想定)。
- overlay(連敗で縮小)で下がったDD枠を使ってサイズを上げる = **再レバ**。順序: ①overlay ON →
  ②数か月フォワードでDD低下を実機確認 → ③空いた枠ぶり risk% を上げる。**検証なしの同時投入はしない。**
- 現運用の確定値(T1): **risk0.3-0.5%/pair・overlay ON → DD≈6-9.4%**。8ペアなら 0.4-0.45% で DD≤10%。

## 6. 報告フォーマット（必須）

戦略の成績を述べるときは**必ず3点セット + 前提**で書く:

```
[戦略名] realistic ≈ +X%/月 (期間=全IS 2021-26, DD≈Y%, risk Z%/pair)
  ├ 楽観(レベル約定/T3)   : +A%/月   ← 上限
  ├ realistic(実測校正/T2): +X%/月   ← これを見出しにする
  └ 実機実測(T1, 有れば)  : +B%/月   ← 最優先
  前提: net(コミ+spread), 期間=..., WF両期間net+ = (OOS +.. / IS +..), 約定=...
```

**1つの数字だけを「月利」として出すのは禁止**(フィル仮定で2-3倍・期間で更に振れるため)。
**見出しの数字は「全WF期間 × realistic(実測校正)フィル」に固定する。** 直近window/楽観フィルは補足扱い。
